# ControlWard Chrome integration audit

Repository reviewed: `https://github.com/martinlepage26-bit/controlward` at commit `dc49e7b6deec7a2cb8e7ec2151387cd0704c9e05` (main, audited 2026-10-23).

- `README.md` says the operational CRM is the native macOS app; the existing `src/` Twenty extension scaffold is formally descope/parked and is not connected to the live workflow. Source: https://raw.githubusercontent.com/martinlepage26-bit/controlward/main/README.md
- `pharos-api/README.md` documents the available Worker contract. `/v1/leads/push` accepts only synthetic test leads or inbound form leads and rejects search/crawl provenance. `/v1/leads` read/ack requires the private ContextWard key. No browser-capture lead-create route is present. Source: https://raw.githubusercontent.com/martinlepage26-bit/controlward/main/pharos-api/README.md
- Native qualification source of truth is `native-crm/Sources/FollowUpOSNative/LeadDefinition.swift`: `Ready`, `Fix`, `Drop`, and `conflict_review`; requires segment, source URL and fetch time, named person from an allowed contact source, title evidence, allowed/fresh trigger, fit line and public route. `rbqUnchecked` holds required construction segments unless RBQ lookup is `matched`; municipality matching is whole-value with case/diacritic folding; unknown location is fail-closed for configured conflict areas.
- `ProspectSearchRun.swift` uses `GuardedLeadTransport` to fetch own-site pages, `SiteExtractor` for evidence, cached RBQ enrichment, and the `LeadDefinition` verdict. `ProspectIngest` in `ProspectLeads.swift` deduplicates by source id, normalized email, phone, then normalized domain and merges into local `leads/prospects.json`.
- `LeadPipelineEnvironment.swift` stores prospects under `~/Library/Application Support/ControlWard/leads` by default and loads the confirmed `icp.json` configuration from app resources. `RBQOpenData.swift` returns no match if name/municipality is ambiguous; it does not read RBQ email, phone, agent, address, or NEQ.

The Worker secrets remain outside browser code. The selected integration boundary is Chrome Native Messaging, using the same native executable and Swift modules. The browser sends only user-reviewed business/site/segment inputs; the native host fetches the selected public business site through the existing guarded transport and applies the existing extraction, RBQ and qualification code. Production Worker routes remain unchanged.
