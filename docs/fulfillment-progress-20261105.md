## Repairs made locally

- **Unsent draft retention:** the actual release walkthrough exposed that generated text was discarded by Save & close. Earlier record-persistence checks did not establish retention of the unsent text. A new optional `outreachDraft` field preserves generated or edited text without treating it as prior contact, changing the cadence or appending sent history. Mark as sent consumes that draft only after a successful save. Existing workspaces without the field remain compatible.
- **Actual release review:** `CONTROLWARD_REVIEW_ID=<UUID v4>` selects a separate sandbox workspace in normal release builds, with in-memory account stores, rejecting connector/mail transports, ephemeral embedded modules and no notification coordinator. The visible banner identifies review mode. `bin/review-controlward` checks the signed bundle's capability marker before launching and refuses older releases. Tests verify malformed IDs fail, injected credential stores and transports receive zero calls, local writes survive reload, and existing notification requests remain untouched.
- **CRM save failures:** ordinary lead, contact, company, opportunity, task, note, signal, audit, saved-view and business edits now commit before publishing their new state. Related lead/task/outcome changes share the transaction. Editors retain drafts and display a persistent error when storage is unavailable; discovery marks a result added only after saving. Follow-up logging updates its caller's draft only after success. Local automations also use the transaction boundary. Sixteen new cases reproduced the original failure; the expanded suite now passes 18 failure-and-retry cases, including reload checks. Connector import/outbox routines are outside this repair's scope.
- **Preview mail isolation:** acceptance builds default to an in-memory mail token store and rejecting transport before account state is queried. Preview connect cannot open OAuth; refresh and periodic polling do nothing; client-ID changes do not touch owner preferences. Injected fake live behavior remains available to tests explicitly. The preview main entrypoint requires a dedicated data directory and never falls back to the owner's normal workspace.
- **LeadGen file intake:** the running-app replay check reproduced duplicate leads and signals. Imports now commit atomically, retain stable event or normalized-identity receipts across renamed files and relaunches, recognize old event evidence, and preserve existing owner edits. Ambiguous email matches refuse the whole batch. File imports remain non-inbound sources, and supplied scores are attributed to the file. Five new regression cases passed; the repaired UI imported one event, then reported zero imported and one already recorded on retry.
- **One reminder plan:** a converted lead uses its task notification; an unconverted lead uses a lead notification. Saves, conversion, closing, deletion and restore reconcile the same plan. Queued changes execute serially, preventing a slow reschedule from recreating a cancelled reminder. Clearing a date propagates in either direction. Recording a new date reopens the completed next-action task; automatic due-follow-up creation persists that task's link and does not recreate completed actions. Older automatic task links are recognized when planning notifications.
- **Notification errors:** automatic startup does not request permission. The explicit Schedule reminders action distinguishes not-yet-requested, denied, unavailable and API failure. Operations retains the result after the toast disappears and reports partial scheduling failure accurately.
- **Restore form state:** Settings now refreshes the business name, industry and automation setting when the stored workspace changes. The previous form kept an old name after a successful restore, allowing a later Save to overwrite the restored name.
- **Discovery usability and evidence:** an empty search explains the result; the 15-second cooldown updates without requiring another UI interaction. A public business category remains evidence, rather than becoming a requested service. Scoring evidence lists earned points and gives no points to blank contact fields.
- **Release build:** the first packaging attempt exposed a release-only optional-type inference error in reminder initialization. The type is now explicit in both build configurations; a clean Swift release build passed afterward.
- **Preview startup:** Launch Services opens the preview bundle; fixture follow-up dates are relative to today. Production signing credentials are not inspected during local builds.
